## v0.4（2026-10-19）· 城市视图可读性 + P1 首批能力

本轮不改数据模型，全部在现有 repository / store / scene 分层内完成。

### 1. 城市视图聚焦（L2 可读性）

- 进入城市后，除当前城市外的所有城市板块压成暗色剪影（`SceneManager.setCityFocus`），
  只保留极淡的省界走向，作为空间参照。
- 退出城市（Esc / 返回）自动恢复区域总览亮度。
- 区域总览区分「已录入 / 待录入」：已录入城市顶盖自发光 0.24、描边 0.95；
  待录入城市压到 0.035 / 0.2，可下钻的城市在画面上自然浮现。
- 顶部遥测改为 `3/41 市 · 29 区县`，直接说明哪些城市有内容。

涉及：`src/scene/SceneManager.ts`、`src/app/sandbox.ts`、`src/components/hud/TopBar.tsx`

### 2. 城市概览卡（P1：3D 兜底入口）

- 左侧索引顶部新增城市简介、录入进度（`11/13 区县已录入`、触点数）与热门区县快捷胶囊。
- 数据取自 `City.intro` 与 `featuredDistricts`，不新增字段；全部内容仍是「点区县 → 抽屉」的同一路径。

涉及：`src/components/hud/LeftIndex.tsx`、`src/styles/app.css`

### 3. 景点 / 美食关联推荐（P1）

- 景点卡新增「同区县还有」：同区县其余景点按热门优先，最多 3 条，点击直接切换定位与卡片。
- 美食卡新增「同区县还有」：同区县其余美食，点击切换美食卡。
- 复用已有的 `spotsByDistrict` / `District.foods`，无额外请求。

涉及：`src/components/cards/LeafCard.tsx`、`src/styles/app.css`

### 4. 收藏导入 / 清空（P1：数据导入）

- 收藏面板支持导入 JSON：兼容导出文件（`{ favorites: {...} }`）与裸 `{ districts, spots }`。
- 导入时按当前数据集校验 id、自动去重并与现有收藏合并，非法文件给出明确提示。
- 「清空」为两步确认（4 秒内二次点击生效），避免误操作；清空后同步移除区域总览上的收藏触点。

涉及：`src/app/sandbox.ts`、`src/stores/ui.ts`、`src/components/cards/FavoritesPanel.tsx`

### 5. Pin 柔性避让

- 城市尺度下同一区县内景点相距常不足 1 个世界单位（屏幕上只有几像素），直接落点会叠成一团。
- `declutterPins` 对相互重叠的 pin 做有上限的柔性排斥（最近间距 0.52、最大偏移 1.15 世界单位），
  只推开重叠项、不改变整体方位，保持「景点在所属区县板块上」的语义。

涉及：`src/app/sandbox.ts`

## v0.5（2026-10-19）· 数据管理（本地可写内容层 + 编辑器）

本批把「离线可编辑知识库」这个产品核心承诺落地：静态 JSON 只读，所有编辑落在 localStorage 覆盖层，
通过 `applyEdits` 合并进运行态，与 Tauri 适配层解耦——接 Tauri 时只换 repository 实现，UI 不动。

### 1. 本地内容覆盖层（存储层）

- `src/data/contentEdits.ts`：`ContentEdits = { districts, spots, deletedDistricts, deletedSpots, updatedAt }`，
  `STORAGE_KEY = 'ds.contentEdits.v1'`。
- `applyEdits(bundle)` 合并静态内容与本地覆盖：覆盖项整条替换；删除项剔除并同步清理
  `district.spots` 与 `city.districts` 的引用；返回全新对象，不修改入参。
- `staticRepository.loadContent()` 改为 `读原始 → applyEdits → 返回`；`mutateEdits` 写完即 `invalidateContent()`。
- `repository.ts` 扩展 `readContentEdits / saveDistrictContent / saveSpotContent / deleteDistrictContent /
  deleteSpotContent / resetContentEdits`，全部由 browser 实现，未来 `tauriRepository` 可整体替换。

涉及：`src/data/contentEdits.ts`、`src/data/repository.ts`、`src/data/staticRepository.ts`、`src/stores/data.ts`

### 2. 内容校验（运行态 + 构建期）

- `src/data/validate.ts`：`ALL_TAGS`、`validateSpot / validateDistrict / validateDraft / isEmptyContent`。
  坐标边界 经度 73–135.5、纬度 3–54；日期 `^\d{4}-\d{2}-\d{2}$`；空名/一句话/简介、悬空引用、重复 id 报错；
  >4 标签、美食缺分类、超长行程为建议。
- `scripts/validate-content.mjs`：`npm run validate` 在构建链路（`build-content → validate → tsc → vite build`）
  中跑通，校验结构 / 标签 / 日期 / 坐标 / 引用方向（内容→城市归属，不要求城市全量区县都有内容）；error 退出码 1。

涉及：`src/data/validate.ts`、`scripts/validate-content.mjs`、`package.json`

### 3. 数据面板（编辑器 UI）

- `src/components/data/DataPanel.tsx`：模态编辑。左栏按城市分组列出区县（已编辑打点 + 景点数）；
  主区含 基础信息 / 内容块 / 美食 / 景点 四段，实时 `validateDraft` 内联报错，dirty=false 或 error>0 时禁用保存。
- 保存走 `applyDistrictEdits`（写 spots+district、更新 map、标已编辑）→ `refreshPins()` + `updateMarkers()` 让 3D 与抽屉即时反映。
- 打开优先定位当前正在看的区县（`useNavigation.activeDistrictId`）。
- `src/components/data/fields.tsx`：`Field / TagPicker / PeopleEditor / FoodsEditor` 复用表单件。
- 顶部 `TopBar` 新增 `✎ 数据` 入口，显示已编辑区县数角标；`Shell` 的 Esc 优先关面板。

涉及：`src/components/data/DataPanel.tsx`、`src/components/data/fields.tsx`、`src/components/hud/TopBar.tsx`、`src/app/Shell.tsx`、`src/styles/app.css`

### 4. 导入 / 导出 / 重置

- `exportContentBundle(districtId?)` 下载单个区县或全量 bundle（`format: 'district-sandbox-content@1'`），可回写 `public/content`。
- `importContentBundleFile(file)` 校验后并入当前数据集：支持「仅景点」bundle 挂回已有区县；按已知 id 去重，非法项跳过并提示。
- `removeDistrictContent`（两步确认）整条剔除区县及其景点；`resetContent`（两步确认）清空覆盖层恢复静态内容。

涉及：`src/app/sandbox.ts`、`src/stores/data.ts`、`src/stores/ui.ts`

## v0.8（2026-10-20）· 体验修正 + 本地照片库

一次性回应用户 6 条反馈：场景抬升截面、区县自有美食、去过标记、城区文案、本地照片库、抽屉标题间距。

### 1. 选中抬升的截面重做（场景）
- 问题：城市 / 区县板块被选中或悬停时整体抬升，侧壁直接暴露、板底悬空，像一块漂浮的平板。
- 处理（`src/scene/plates.ts`、`src/scene/SceneManager.ts`）：
  - 板块轮廓线由「整条挤出棱线」改为「只描顶部轮廓」（`LineLoop`），侧面是一整块干净的面，
    不再露出一排细竖线；碎岛型区县（如淳安）本身是多边形，属数据形态，非缺陷。
  - 每个板块新增**抬升基座**：同形内缩 0.84 的柱体，从地面连到板底，顶部略高过板底 0.02 避免共面 z-fighting；
    基座带语义色微光与轮廓线，在暗场里读作「展台」而不是浮空平板。
  - 抬升由瞬时赋值改为**帧率无关的平滑过渡**（约 0.3s 到位 94%），基座高度跟随板高。
- 注意：淳安这类多岛区县的侧面仍是多根小柱，是地理数据形态；城市级板块为单轮廓，侧面已干净。

### 2. 区县详情改为「本区县美食 + 特产 · 非遗」
- 问题：抽屉里的「城市美食榜」取的是 `currentCity.foods`，选淳安县显示的是杭州美食。
- 处理：抽屉改为展示 **本区县 `foods`**（标题「在地美食」），点击仍走 `openLeaf` 美食卡；
  新增「特产 · 非遗」板块。城市级美食榜只留在城市面板（`CityPanel`），不再侵入区县抽屉。
- 数据模型：`District.specialties?: { name, kind: '特产'|'非遗', note }[]`；
  内容源 `scripts/content/*.mjs` 每个区县对象下新增 `specialties: [[名称, 类型, 说明], …]`，
  由 `build-content.mjs` 映射入 `districts.json`。本轮为 **35/38 区县录入 62 条**（徐汇 / 杨浦 / 长宁暂无把握条目，
  留空由用户在编辑器补；全部内容沿用「公开资料整理 · 待人工复核」口径）。
- 编辑器：`DataPanel` 新增「特产 · 非遗」段（类型二选一 + 名称 + 说明），`validate.ts` 同步校验
  （名称必填、类型只能是特产 / 非遗、超过 8 条警告）。

### 阶段 C 补丁：横穿中线的真正根因（基座被压扁）

上一版把「地图中部一根横线」归因于 `GridHelper` 的中心线色（已顺手统一为单色），但用户复看后指出**线还在**。这次用射线拾取 + 投影包围盒扫描定位到真凶：

- **现象**：安徽左侧、上海右侧各露出一段数十字像素的细横线（金色 / 青色 / 带暗蓝面），恰在地图中央纬线 z≈0 上。
- **根因**：`createPedestal` 里用 `mesh.scale.y = 0.001` 把基座「压平隐藏」。但基座是先 `rotation.x = -PI/2` 旋转的挤出体，**高度方向是局部 Z 轴（挤出方向），局部 Y 旋转后变成世界 Z（南北）**。`scale.y = 0.001` 压的不是高度而是「南北向足迹」——每个城市的基座被压成一片 1 单位高、横跨整城东西宽度的**薄墙**，贴在 z≈0 的中央纬线上；薄墙与板块在 z≈0 处足迹不重合的部分就露出板外，形成那两段细线（`stepPlateLift` 里同轴的 `pedestal.scale.y` 动画也是同一处错）。
- **修复**：`createPedestal` 改 `scale.z = 0.001`；`stepPlateLift` 里基座高度动画改用 `scale.z`。修复后基座足迹不再变形（`scale.y === 1`），静止时高度 0.02 藏于板内；选中抬升时 `scale.z` 长到 1 倍抬升量，仍是原来的「展台」效果（实测：选中浦东 targetY=0.55、板 y=0.54、基座 scale.z=0.56）。
- **验证**：`scripts/regression-phaseC.mjs` 新增 #7b「基座未压扁（无横穿细线）」——210 个城市基座 `scale.y≠1` 的数量为 0、最大高度 0.02、全场景「投影宽>40px 且高<9px」的细长板块为 0；并新增诊断脚本 `scripts/diag-sliver.mjs`（射线+投影扫描定位细线对象）与 `scripts/diag-pedestal.mjs`（基座缩放/归属）。回归 12/12 PASS。
- **经验**：给旋转过的挤出体改尺寸，先确认「挤出方向落到哪个世界轴」——`rotation.x=-90°` 时高度只能走 `scale.z`；`scale.y` 动的是平面足迹，且因为几何点用的是世界坐标，压足迹会把它整体拉向 z=0，看起来就是一条横穿全图的细线。

## v0.8（2026-10-20）· 区县被城市板压住 / 取景过大 / 爱心倒置 / 照片墙

### 1. 区县分割线「怎么改都看不清」——真因是整层被压住

### 2. 点城市「放大的太大」
- 旧取景 `frameTo(districtBox, 0.7, 0.62)`：factor 0.62 是「比刚好装下还近 38%」，且只按整屏算，没考虑左侧索引（240px）和右侧城市面板（372px）各压掉一块 —— 城市实际被推到面板底下。
- 修复：`frameTo` 增加可选 `view`（可用视区，像素），按可用宽高反算距离，并把内容平移到可用区中心（沿相机 right/up 向量偏移 `(可用区中心 − 屏幕中心) × 世界/像素`）。`usableView()` 取 `x:240 / right:372 / top:88 / bottom:76`；城市下钻改为 `frameTo(box, 0.7, 1.06, 0, usableView())`。
- 实测：杭州市投影 `x[232,1016]`、上海市 `x[281,1004]`，都落在可用区 `x[240,1068]` 内，占可用宽 87%~92%（改前 102%~105%，越界）。

### 3. 收藏的小红心不好看 / 颜色不行 / 上下颠倒
- 旧轮廓是手搓贝塞尔（three.js 示例心形），其两个圆瓣在**下方**、尖端在**上方** → 渲染出来是倒置的爱心（用户说的「上下颠倒」）。直接翻转会带来法线/缩放问题，改为用经典心形参数方程生成：
  `x = 16sin³t / 16`，`y = (13cos t − 5cos2t − 2cos3t − cos4t) / 16`，84 段折线成 `Shape`，再 `computeBoundingBox()` 居中 → 天然「上方两瓣 + 下方一尖」。

### 4. 照片墙：照片不显示 / 放大显示不完整
- **放大不完整**：CSS 只给 `.smart-img`（SmartImage 组件）写了 `object-fit: contain`，而本地照片走的是裸 `<img class="wall-media-img">`，落回全局的 `object-fit: cover` → 被裁掉一截。现在 `.wall-focus-img` / `.wall-stage-img` 同时覆盖 `.smart-img` 与 `.wall-media-img`，聚焦态容器改为 flex 居中、图片 `width/height: auto` + `max-height:74vh`（容器自适应图片，不再拉伸裁切）。

## v1.6 · 地形改用真实地理数据

用户反馈「湖就画个圆，山坡也不形象，不能根据真实地图来吗？」——原来的地形是写意占位：湖泊用椭圆近似、山用圆锥体。这一版换成真实数据驱动。

### 数据来源（全部构建期抓取，运行时零网络请求）

| 图层 | 来源 | 说明 |
|---|---|---|
| 高程 | AWS Terrain Tiles（Terrarium 编码 DEM，源数据 SRTM/ASTER/ETOPO） | z8 瓦片 49 张，约 550m/px |
| 湖泊 / 水库 | OpenStreetMap（Overpass API） | `natural=water` + `water=lake/reservoir/basin`，≥2km² |
| 河道 | OpenStreetMap（Overpass API） | `waterway=river` 主干 + 运河，18 条主要水系 |

产物落在 `public/geo/terrain/`（约 480KB）：`height.json` / `height.bin`（205×240 高程网格，Uint8 量化）/ `mask.bin`（陆地掩膜）/ `water.json`（241 个湖）/ `rivers.json`（107 段干流）。
重新生成：`npm run terrain`（`--force` 忽略缓存）。DEM 瓦片与 Overpass 原始响应缓存在 `.cache/terrain/`（已 gitignore）。

### 实现要点

- **网格投影**：DEM 是 Web Mercator，项目是等距圆柱投影。不直接搬瓦片，而是按项目自己的 `projectPoint` 在世界空间建规则网格，再反解经纬度采样 DEM，保证地形与板块严丝合缝。
- **陆地掩膜**：用 `cities.geojson` 的 41 个市多边形做点在多边形内判定，格心不在陆域的三角形直接不生成 —— 海面干净，没有一块地形浮在海上。
- **垂直夸张 26 倍**：1 世界单位 ≈ 7.5km，黄山 1864m 真实只有 0.25 单位，按原比例完全看不见。夸张后主峰约 6.4 单位，明显高出板块（2.6）又不失真成尖刺。**这是示意用法，不是测绘比例**。
- **海拔配色**：低地墨绿 → 丘陵黄绿 → 山地褐 → 高山灰 → 峰顶雪，按海拔线性插值到顶点色。
- **光照补偿 0.28**：场景打光很亮（半球光 1.3 + 方向光 2.4），正常亮度基色会被放大三四倍溢出成灰白。基色压到 0.28 再交给 PBR，出来才是设计要的中低明度。
- **高度平滑**：3×3 加权（1-2-1）一次，把 DEM 落到 4km 网格后的锯齿磨平，山体连贯。
- **水体合并**：241 个湖合并成 1 个 BufferGeometry（1 次绘制），安卓端不会因为几百个 draw call 掉帧。

### 踩到的坑

1. **闭合环被 DP 简化成 2 个点**：Douglas-Peucker 用「首尾两点」作初始直线，闭合环首尾是同一点，连线长度为 0，所有中间点的垂直距离恒为 0，于是全被判可丢弃 —— 337 个大湖（含太湖、千岛湖）整片消失。修法：闭合环先去重复尾点，再以「离首点最远的顶点」为第二锚点拆成两段分别简化（`simplifyRing`）。
2. **水体左右镜像**：原代码把投影后的 `-y` 存进 `Vector2` 再 `rotation.x = -PI/2`，两次取负抵消，湖被翻到地图另一侧。新实现直接用投影后的 `y` 建世界坐标 `(x, WATER_Y, -y)`，与板块同向。
3. **bbox 外扩带进省外水体**：按行政区包围盒抓数会捎上鄱阳湖等邻省大湖。按环质心做陆域判定过滤掉。
4. **空间几何量别用绝对经纬度算**：轴对齐包围盒粗筛要先做，否则 210 个环 × 49200 个格心会慢到无法接受。

### 可调参数

- `scripts/build-terrain.mjs`：`GRID_LONG`（网格密度）、`MIN_WATER_AREA`（湖面积阈值）、`MAJOR_RIVERS`（水系白名单）、`SIMPLIFY_TOL`（岸线简化容差）。
- `src/scene/terrain.ts`：`EXAGGERATION`（垂直夸张）、`LIGHT_COMP`（光照补偿）、`ELEV_STOPS`（海拔配色）。

## v1.7 · 地形不再吃掉城市边界 + 观感重调

用户反馈：「有了地形为啥城市之间的分隔看不清了，能不能加一个开关显示地形，地形的特效颜色能不能好看一点？」

### 边界看不清的根因与修法

地形是一整块覆盖全省的网格，顶面在板块之上。板块自带的轮廓线画在 `y = 板高 + 0.02`（2.62），
只要该处海拔大于 0 就被埋进山体／平原里 —— 城市形状随之消失。

- `TerrainHandle` 新增 `heightAt(x, z)`：按项目自身的等距圆柱投影反解经纬度，再对地表高度网格做双线性插值。
- `SceneManager` 在 `setCityPlates` 时另存一份城市轮廓（`cityRings`），按 ~3.7km 步长采样地形高度，
  沿山形起伏逐段重画一条「贴地边界线」，抬离地表 0.26（高于湖面 0.08 与河道 0.16）。
- 41 个城市的线合并成一个 `LineSegments2`，**只多 1 个 draw call**；按省份色提亮并略降饱和
  （浙江省的绿原本和地形同族，等同于隐形）。下钻区县时随地形一起隐藏。

### 踩坑：泛光把整块地形冲成白色

初版边界线用「省份色 lerp 白 0.34」，亮度越过 bloom 阈值（0.62），满图亮线在 0.7 半径的
bloom 里互相叠加，斜视角下整块地形糊成一片白光。最终把线色压到阈值以下（`offsetHSL(0,-0.2,0.18)`
再乘 0.74），改用对比度而非发光来拉层次 —— 这也是判断「亮线 + 泛光后处理」是否过量的实用标准。

### 观感重调

- **配色**：低地冷青绿 → 丘陵黄绿 → 山地暖赭 → 岩灰 → 雪顶（9 档）。单一绿色系读不出地势。
- **坡度明暗**：按法线 Y 分量再压一档（0.74 + 0.36·ny），俯视时方向光照不出起伏，靠它补体积感。
- **等高线**：每 220m 一道 1px 冷白刻线，用 `fwidth` 让线宽恒定，并按屏幕导数淡出 ——
  省视角下等高带密到连成白雾，只有放大看山形时才显出来。
- **水面**：PBR 材质在强光 + 环境贴图下无论怎么调基色都会被反射成灰白，
  改成自发光式 `MeshBasicMaterial` + 自定义水纹着色器（两组错频正弦提亮），水色才留得住孔雀蓝。

### 开关

顶栏新增 `⛰ 地形` 开关（手机端只留图标）：原来只藏在「设置 → 地图图层」，
手机端更是连设置入口都没有。设置面板里的开关保留，两处同步 `ui.terrain`。

## v1.8 · 地形铺满、下钻可见、标记回到地表

用户反馈三条：「江苏右上角地形覆盖不全，一直会闪后面蓝色的背景」「选择一个市、一个区县能不能也显示地形」「有了地形之后小红旗和爱心也看不见」。

### 一、海岸线闪蓝：三层原因叠在一起

1. **地形与板块顶盖共面**：平原高程只有几米，换算成世界坐标不到 0.05，地形网格与城市板块顶面几乎贴合。远视角下深度精度不够，两者反复争夺深度，闪出来的正是板块的深蓝底色（江苏 `0x38bdf8`）。
   → 地形基准面抬到 `LAND_TOP + 0.08`，材质叠 `polygonOffset(-2)`，板块顶盖反向 `polygonOffset(+1)`。三层一起，任何距离都稳定。
2. **网格裁剪留缝**：地形三角形按「四角格心都在陆域内」生成，海岸线一带必然空出半格到一格（约 4km），空出来的地方就是板块顶盖的蓝。
   → 新增**陆域底板** `setLandBase()`：把 41 个城市的真实多边形三角化成一层低地色平面，垫在地形之下、板块之上（`LAND_TOP + 0.03`）。缝隙从此露出陆地色。
3. **等高线的 0 米陷阱（真正让整片发白的原因）**：`fract(0 / 220)` 恒为 0，所有海拔恰好为 0 的格子（苏北平原、湖面、DEM 缺测，占陆地 12%）都被判成「正好压在等高线上」，整片区域被加上一层白雾。放大后表现为一块块边缘呈阶梯状的浅色斑。
   → 用 `smoothstep(2, 8, 海拔)` 把 0～6m 的平坦区排除在等高线之外。

顺带修掉底板三角形绕序反了导致整块被背面剔除的问题（底板此前等于没画）。

### 二、下钻也能看地形

- `applyTerrain()` 不再在 `district` 层隐藏地形，改为**自适应竖向缩放**：`reliefForTop(区县多边形, 板块顶面)` 取该市范围内最高地形，反算一个刚好不会戳穿区县板块（顶面 3.63）的倍数。盐城这类平原城市算出来封顶在 1（周边山川保持真实比例），黄山、杭州这类山区城市才需要压扁。
- 压扁时顶点色向低地色混 55%，弱化「按海拔分的色块」，让地形退回成安静的地貌底图；高大起伏交给板块，视觉重心不乱。
- 竖向缩放不能靠 `group.scale.y`：非等比缩放会把法线按 `1/relief` 放大，原本几度的缓坡被照成侧壁，整片平原变成互不相连的色块。改为**直接改顶点高度 + `computeVertexNormals()`**。
- 城市边界线在区县视角也画，周边城市因此仍有分界，不会变成一整片纯绿。

### 三、红旗与爱心回到地表

- 标记落点从「板块顶面 + 0.32」改为 `terrain.heightAt(x, z) + 0.06` —— 插在山地上就是山地的地表，不再被山体埋住。
- 地形是异步加载的（先建标记、后挂地形），新增 `applyMarkerGround()` 在挂载 / 开关 / 换层时把已有标记重新插回地表。
- 标记像素尺寸调大（旗 42→48，心 28→36）。
- 修掉一个真 bug：`setCityFocus` 进城市时关掉 `cityMarkerGroup`，而 `clearDistrictPlates` 里 `focusedCityId` 先被置空，导致 `setCityFocus(null)` 早退 —— **在城市视图逛一圈回到总览后，所有旗子和爱心再也不出现**。这条很可能就是用户说的「看不见」。

- `src/scene/terrain.ts`：`TERRAIN_BASE`（基准面抬升）、`CONTOUR_STEP`、`EXAGGERATION`、`ELEV_STOPS`。
- `src/scene/SceneManager.ts`：`MARKER_SCREEN_PX`、`rebuildBoundaryOverlay` 的 `LIFT`。

## v1.9 · 河道裁到陆域：地图外不再飘水系

用户反馈：「地形是不是把多出来的河流超出了实际的地图了？特别是左侧」。

### 根因：Overpass 的 bbox 只负责「选中」，不负责「裁剪」

`way["waterway"="river"](bbox)` 的语义是「与 bbox 有交集的 way」，返回的 `out geom` 却是**整条 way**。于是长江上游段一路画到 `114.51°E`（本图西界 `114.83°E`），京杭大运河越过北界到 `35.29°N`，赣江、信江这些**根本不在江浙沪皖图内**的江西水系也全部画了出来 —— 在屏幕上就是左侧、下侧多出一把悬空的虚线。

### 修法

- 新增 `clipLineToLand()`：按 ~1.2km 加密（原 way 顶点间距可达数十公里，不加密断口会歪出十几公里）→ 逐段以中点做陆域判定 → 连续在陆上的归为一段 → 短于 `MIN_RIVER_RUN_KM`（6km）的尾巴丢弃。一条河被切出多段时按多段输出（长江出省再进省的场景）。
- 简化后再兜一刀：DP 削角会让个别顶点又落到边界外几百米，`filter(inLand)` 一遍后越界顶点归零。
- **界湖同样处理**：皖鄂交界的龙感湖有 31/116 个顶点在省外（最远 7.9km），苏鲁交界的石梁河水库 18/73（7.0km）。原先只按质心过滤（质心在本省就留），于是半个湖挂在板块外。现在按顶点裁掉省外部分，环自然以直弦闭合贴住省界（龙感湖 257→173km²，与安徽实际辖域相符）。

### 结果（构建期校验）

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 河道顶点出界 | — | 0 / 1193 |
| 水体顶点出界 | 56 / 18078 | 0 / 18022 |
| 河道经度范围 | 114.51–122.37 | 115.67–121.95 |
| 河道纬度范围 | 27.06–35.29 | 27.67–34.42 |
| 河道段数 | 107（含 33 段整段在图外） | 78（丢弃 33 段图外） |

## v1.10 · 小旗子 / 爱心：从「一条红线」改成始终面向镜头的贴片

用户反馈：「exe 还是看不到小旗子和爱心」。

### 真相：不是没画，是被视角压扁了

先在预览页注入两条「去过」数据，遍历场景确认对象确实存在：`cityMarkerGroup` 有 2 个子节点、
`visible=true`、位置在 2.79 / 3.29 —— 渲染是正常的。再截图放大看，南京和杭州的位置各有一条
**十来个像素的红色细线**。

原因在几何本身：旧标记是 3D 实体——旗面是竖直的 `PlaneGeometry`，旗杆是竖直的细 `CylinderGeometry`。
默认相机是 **50° 俯角**，视线几乎平行于旗面，于是整面旗被压成正侧投影的一条线，一根 0.038 半径的杆
更只剩一两个像素。于是「有数据、有对象、看不见」。

顺带还有一个次要问题：缩放有 `Math.min(targetWorld / ih, 3.5)` 的上限，远视角时反算值被截断，
标记又比设计的 48px 小一截。

### 改法

- 标记改成 **`THREE.Sprite` + canvas 现画的贴图**（旗子 / 爱心各一张 128×168）。Sprite 是屏幕对齐公告板，
  任何俯角都完整可见，也不再需要用 3D 几何拼杆和旗面。贴图带深色描边，浅绿地面上也立得住。
- 缩放去掉上限：`worldH = MARKER_SCREEN_PX / pxPerUnit`，宽度按画布比例 `128/168`。
  `center.set(0.5, 0)` 让底边对齐锚点，落地点仍由 `markerGroundY()`（地形表面）+ 板块抬升量决定。
- 板块抬升不再直接写 `position.y`，改为记 `userData.lift`，由每帧的 `updateMarkerScales()` 统一合成
  `y = baseY + lift`——贴片高度每帧都在变，写死位置会和缩放打架。
- 释放安全：Sprite 用的是 three 内部**共享几何体**，`disposeObject()` 里单独 dispose 会把所有贴片一起弄坏，
  已跳过 `isSprite`；标记贴图是缓存共享的，`disposeMaterial()` 认 `userData.sharedTexture` 不 dispose 纹理，
  只随 `SceneManager.dispose()` 统一释放。

### 校验

- 注入 2 条去过数据后，`cityMarkerGroup` 子节点类型为 `Sprite`，缩放 `6.44 × 8.45`（对应屏幕 48px）。
- 1:1 裁剪截图：旗面、旗杆、金球、爱心轮廓全部清晰可辨；同一城市同时有「去过 + 收藏」时按槽位错开不重叠。

## v1.11 · 标了淳安，省视角杭州没插旗

用户反馈：「我在淳安点了去过，正常杭州应该也去过了，那么省视角杭州也应该插个旗子，现在我还是看不见」。

### 根因：区县→城市用「名称」当了「id」

`updateMarkers()` 里本来有这段逻辑，看起来没问题：

```ts
const d = data.districts[did];
if (d?.city) visitedCities.add(d.city);   // ← d.city 是 "杭州市"
```

但内容里 `district.city` 存的是城市**名称**（`"杭州市"`），而 `visitedCities` 这个集合随后被当作
**城市 id** 传给 `setCityMarkers()`。`fillMarkers()` 用 `records.get(item.id)` 在 `this.cities`（以 `330100`
这样的编码为键）里查，`"杭州市"` 必然查不到，于是 `continue` —— 静默丢弃，一个旗子都不建。
数据、订阅、渲染链路全都是通的，只有这一步的 id 翻译错了。

`toggleVisitedDistrict()` 也确实只写 `visitedDistricts`，不会顺手把所属城市加进 `visited`，
所以省视角完全依赖这步翻译。

### 修法

- 统一用行政区划编码推城市 id：`cityIdOfDistrict(did)` = 区县码前 4 位 + `00`
  （`330127` 淳安 → `330100` 杭州）。这个函数本来就有，只是这里没用上。
- 顺手补了直辖市的兜底：`310101` → `310000`，且改为按码前缀 `31` 判断，未录入内容的区县也能推对。
- 加一道存在性校验：推出来的 id 必须能在 `data.cities` 里找到才加入，避免脏 id 再进渲染层。

### 校验

- 只注入 `visitedDistricts: ['330127']`（`visited` 为空）→ `cityMarkerGroup` 出现 1 个
  `{ plate: '330100', kind: 'visited' }`，截图里杭州位置有红旗。
- 进杭州城市视图 → `districtMarkerGroup` 出现 `{ plate: '330127' }`，淳安板块上有红旗。
- 老用户数据无需迁移：`visited` 里本来就没被污染，下次启动 `updateMarkers()` 会重新推导。

## v1.12 · 太湖水干了：水面被湖底地形盖住

用户反馈：「你有没有发现太湖水都干了」。

### 现象与排查

太湖位置是一块**干燥的凹地**：看得见湖岸轮廓，湖里却没有水。逐层排查：

1. 数据层没问题 —— `water.json` 里太湖 442 个顶点，经纬度范围正是 `119.9–120.6°E / 30.9–31.5°N`。
2. 渲染对象也在 —— 场景里那个 `MeshBasicMaterial` 的合并水体网格包含全部湖，`visible=true`。
3. 把水体材质刷成洋红（`0xff00ff`）：**只有岸边一圈细线是洋红，湖心完全没色**。说明水面网格存在、位置也对，但被什么东西挡住了。
4. 采高度：太湖水面 `y ≈ …`，而 `terrain.heightAt()` 在湖心采样只比水面低 **0.03–0.08 个世界单位**。
5. 对照组验证：把水面整体抬高 0.5 → 立刻满湖蓝；把水面还原、只加 `polygonOffset` → 也是满湖蓝。

### 根因

`WATER_OFFSET = 0.08` 只是个「防共面闪烁」的经验值，但**深度缓冲精度是按整个视锥分的**。总览视角下相机距离约 60 单位、`near/far = 0.1/200`，24 位深度的有效精度在这个尺度上只有 0.1 上下——0.08 的高差直接落在噪声里，像素深度比较时水面输给地形，被 `depthWrite:false` 的地形正常覆盖掉。

小湖因为地形网格顶点少、插值误差大，反而偶尔漏出来；太湖又大又平（整个湖面在同一高度、跨越上百个网格单元），误差稳定地偏向「地形更高」，于是整片消失。这也解释了为什么以前看千岛湖、洪泽湖好像有水，偏偏太湖没有。

### 修法

- 水面材质加 `polygonOffset: true, polygonOffsetFactor: -4, polygonOffsetUnits: -8`——直接改光栅化阶段的深度值，不受世界尺度影响，比继续加大 `WATER_OFFSET` 靠谱（抬高水面会让岸边出现一圈悬空的「水墙」）。
- 顺手把 `WATER_OFFSET` 0.08 → 0.12、`RIVER_OFFSET` 0.16 → 0.2，让岸边几何也更稳一点（仍远小于 1 个地形色阶，视觉上无感）。

### 校验

无锡 / 苏州城市视角 + 总览三处截图：太湖、洪泽湖、巢湖、千岛湖全部是连续蓝色水面，湖心无残留陆地斑块，岸边没有悬空水墙。

## v1.14 · 天气图层：阴天不再下雨 / 下雪，并给出「此刻」实况

### 现象

用户连着两次反馈：进杭州市，3D 里一直在下雨（有时像下雪），可杭州当时是阴天。
先怀疑是天气码取错（`daily[0]` 当日概况 vs `current` 此刻），改完仍不对 —— 于是直接拉接口核对：
杭州此刻 `current.weather_code = 3`（阴），13 个区县全是 0 / 1 / 2 / 3，根本没有降水码。

### 真因

`WeatherFX.setRegions` **从不判断天气类型**：传进来多少个区域就建多少个粒子场，
晴 / 多云 / 阴 / 雾 一律按「雨」来画（`isSnow = false` 的蓝色雨丝）。
所以「只要这一层拉到过天气，天上就永远在飘雨」——跟天气码无关，是渲染侧漏了过滤。

### 改法

- `weatherFX.setRegions`：只保留 `rain` / `snow` 两类建粒子，其余不建、已建的移除；
  雨 ↔ 雪 切换时（`userData.isSnow` 变化）销毁重建，避免「昨晚下雪、现在下雨还在飘雪花」。
- `meta.weatherKind`：显式列出雨码（51–67 / 80–82 / 95–99），未知 / 异常码不再兜底成 rain，改判 cloudy。
- `SceneManager.setWeather`：省视角天气 key 是 `city:<id>`，城市板块 key 是纯 id，查表前剥前缀（原来整层匹配不上）。
- `stores/weather.ts`：缓存 TTL 分级 —— 带 `current` 的按 30 分钟重拉，纯预报仍 3 小时。
- `WeatherCard` 顶部加**「此刻」实况条**（现象 + 温度 + 观测时刻），与 3D 图层同源，可直接核对。

### 校验

- 逻辑层：esbuild 打包 `weatherFX` 跑 node 断言 —— 阴 / 晴 / 多云 / 雾 → 0 粒子；一雨一阴 → 1；
  雨 → 雪 颜色 `acd2ff → ffffff` 且 `isSnow = true`；再转阴 → 0。
- 端到端：无头 Chrome 进杭州，实况条显示「阴 16° 此刻 23:30 实测」，今日阴 / 明日阵雨 94%，0 pageerror。

## v1.31 · 照片墙预览修复 + 编辑器工具栏真正钉住 + 详情头部留白（v0.9.20）

用户反馈三条：① 手机写游记时富文本工具栏被键盘顶走、点不到；② 照片墙「预览效果非常差」
（图片被压成细条）；③ 区县 / 市区详情「头部上面的空间留得有点大」。

### 1. 照片墙被压成细条 —— 真正的根因是 CSS Grid 行高塌陷
- 表面看是「懒加载没生效 / 图太糊」，实测 `.wall-tile` 被压成 **9px**，内层 `.wall-tile-img`
  却是 273px（溢出被 `overflow:hidden` 裁掉）→ 一行行细条，31 张全挤进一屏。
- 根因：`.wall-gallery` 是 `display:grid`，行高默认 `auto`，按「内容的 max-content 高度」
  估算；而比例盒（`aspect-ratio` / `padding-top:75%`）在横向宽度「不确定」的 max-content
  阶段会被算成 0 —— 整行塌成只剩展签的 9px。
  （上一版把 `aspect-ratio` 换成 `padding-top:75%` 也没用，二者是同一类陷阱。）
- 修法：`.wall-gallery { grid-auto-rows: min-content; }`。`min-content` 会先按**确定的列宽**
  结算比例盒，行高恢复（手机上 1 列约 275px 高）；画廊回到可滚动（scrollH ≈ 9400 vs 603），
  基于 `IntersectionObserver` 的懒加载才真正生效（打开瞬间只取 **2/31** 张，而非全量）。
- 回归脚本 `scripts/verify-wall-v19.mjs` 改量 **`.wall-tile` 自身高度**（原来误量内层图片盒，
  才没发现父级塌陷），3/3 通过。

### 2. 富文本工具栏「被键盘顶走」—— 改成结构固位，不再依赖 sticky
- 旧实现：手机端 `.note-editor-scroll` 整块滚动，`.rt-toolbar` 靠 `position:sticky` 顶住；
  Android WebView 在键盘弹出、自动滚到光标时经常让 sticky 失效，工具条被顶出屏幕。
- 修法（纯 CSS，桌面/手机一致）：
  - `.rt-wrap` 改 `display:flex; flex-direction:column; flex:1 1 auto; min-height:0;`
  - `.rt-toolbar` 去掉 `position:sticky/backdrop-filter`，改 `flex:none;` —— 它是 `.rt-wrap`
    顶部的**不滚动横条**，下面只有 `.rt-body` 滚动，天然钉在编辑区顶部。
  - `.rt-body` 加 `flex:1 1 auto; min-height:0; overflow-y:auto;`
  - 手机端 `.note-editor-scroll { overflow:hidden; }`（外层不再滚动，滚动只发生在 `.rt-body`）。
- 新增 `scripts/verify-editor-toolbar.mjs`：撑满正文后把 `.rt-body` 滚到底（scrollTop 3608），
  工具栏 top 183px 纹丝不动、始终在视口内，4/4 通过。

### 3. 详情头部空白 —— safe-area 只在全屏态补
- 手机端 `.place-head` 原 `padding: calc(14px + env(safe-area-inset-top)) …`，对**所有**手机态
  生效；半屏底部抽屉的顶边在屏幕中部、根本不挨着状态栏，刘海机型会叠成「14 + 44」一大截空白
  （区县 `.drawer`、市区 `.city-panel` 共用 `.place-head`，都有此问题）。
- 修法：半屏态 `padding: 12px 16px 12px`；只有 `.drawer.is-full / .city-panel.is-full`

#### 答疑：地图上「蠕动的虚线」是什么
- 是**地形图层里的江河**（`src/scene/terrain.ts` 第 3 节）。河道按真实走向铺成
  `LineSegments2`，材质 `dashed: true`（`dashSize 1.6 / gapSize 1.2`），
  `update()` 里每帧把 `dashOffset` 往回推 → 虚线沿河道向下游移动，模拟水流。
- 只有开启地形（`ui.terrain`）时才创建这套几何，所以「有地形的情况下」才看得到。
- 观感偏「蠕动」是因为河道被拆成逐段 `LineSegmentsGeometry`，每段距离从 0 重新累计，
  虚线相位在段与段之间不连续；想更接近连续流淌，可改成每条河一条 `Line2`（连续距离）再调快 `dashOffset`。

#### 顺带修掉：dist 历史产物累积导致包体虚涨

## v1.35 · 标记在区县层悬空的真正根因（v0.9.26）

### 1. 小红旗 / 爱心在「市 / 区县」视角悬空很高，回全局又正常
- 现象（用户原话）：「区县收藏，小旗子就会悬浮很高，爱心也是，但到全局视角旗子是插在地图上的」。
  PC 与手机端都复现，不是平台差异。
- 根因：**地形高度是绝对世界坐标，标记却被放进一个已经整体抬升过的组里，两者被重复相加**。
  `markerGroundY()` 取 `terrain.heightAt()`（地表基准 2.68 起算的绝对值），而
  `plateTop` 传的是板块的**局部厚度**（城市 2.6 / 区县 1.0）。
  省视角 `cityMarkerGroup.y = 0`，两者恰好重合 → 看不出问题；
  区县层 `districtMarkerGroup` 被 `setDistrictLayerY(DISTRICT_BASE_Y = 2.63)` 整体抬到 2.63，
  再加一次绝对地形高度 → 标记被抬到世界 y≈5.59，而板块顶面只有 3.63，
  凭空多出 ~1.96 个世界单位（1440×900 下 18~30px，标记本身才 40px 高，等于浮起半个身位）。
- 修法：`markerGroundY(x, z, plateTop, layerBase)` 多收一个层基准，
  地形高度先减掉 `layerBase`（区县层 = `DISTRICT_BASE_Y`）再与局部板顶取 max，两套坐标对齐。
- 顺带修掉一个次要漂移：错开摆位的偏移量是按 `worldW` 算的（随缩放变化），
  而落点原先只在建标记时按「单位向量」取样一次 → 缩放后标记飘到别处、脚下高度对不上
  （省视角爱心离地约 2.5px 就是这么来的）。现在 `updateMarkerScales` 每帧按**实际坐标**重取落点。
- 实测（1440×900，地形开）：省 0.2px / 市 0.5px / 区县选中 0.8px，关地形同样 0.2~0.5px；
  手机端 0.3~0.4px。回归里另用一条向下射线确认「脚下 0.05 单位内确实有板块」，
  排除「数值贴地、实际悬在背景上」的假通过。
