## v0.4（2026-10-19）· 城市视图可读性 + P1 首批能力

本轮不改数据模型，全部在现有 repository / store / scene 分层内完成。

### 1. 城市视图聚焦（L2 可读性）

- 进入城市后，除当前城市外的所有城市板块压成暗色剪影（`SceneManager.setCityFocus`），
  只保留极淡的省界走向，作为空间参照。
- 退出城市（Esc / 返回）自动恢复区域总览亮度。
- 区域总览区分「已录入 / 待录入」：已录入城市顶盖自发光 0.24、描边 0.95；
  待录入城市压到 0.035 / 0.2，可下钻的城市在画面上自然浮现。
- 顶部遥测改为 `3/41 市 · 29 区县`，直接说明哪些城市有内容。

涉及：`src/scene/SceneManager.ts`、`src/app/sandbox.ts`、`src/components/hud/TopBar.tsx`

### 2. 城市概览卡（P1：3D 兜底入口）

- 数据取自 `City.intro` 与 `featuredDistricts`，不新增字段；全部内容仍是「点区县 → 抽屉」的同一路径。

涉及：`src/components/hud/LeftIndex.tsx`、`src/styles/app.css`

### 3. 景点 / 美食关联推荐（P1）

- 景点卡新增「同区县还有」：同区县其余景点按热门优先，最多 3 条，点击直接切换定位与卡片。
- 美食卡新增「同区县还有」：同区县其余美食，点击切换美食卡。
- 复用已有的 `spotsByDistrict` / `District.foods`，无额外请求。

涉及：`src/components/cards/LeafCard.tsx`、`src/styles/app.css`

### 4. 收藏导入 / 清空（P1：数据导入）

- 收藏面板支持导入 JSON：兼容导出文件（`{ favorites: {...} }`）与裸 `{ districts, spots }`。
- 导入时按当前数据集校验 id、自动去重并与现有收藏合并，非法文件给出明确提示。
- 「清空」为两步确认（4 秒内二次点击生效），避免误操作；清空后同步移除区域总览上的收藏触点。

涉及：`src/app/sandbox.ts`、`src/stores/ui.ts`、`src/components/cards/FavoritesPanel.tsx`

### 5. Pin 柔性避让

- 城市尺度下同一区县内景点相距常不足 1 个世界单位（屏幕上只有几像素），直接落点会叠成一团。
- `declutterPins` 对相互重叠的 pin 做有上限的柔性排斥（最近间距 0.52、最大偏移 1.15 世界单位），
  只推开重叠项、不改变整体方位，保持「景点在所属区县板块上」的语义。

涉及：`src/app/sandbox.ts`

## v0.5（2026-10-19）· 数据管理（本地可写内容层 + 编辑器）

本批把「离线可编辑知识库」这个产品核心承诺落地：静态 JSON 只读，所有编辑落在 localStorage 覆盖层，
通过 `applyEdits` 合并进运行态，与 Tauri 适配层解耦——接 Tauri 时只换 repository 实现，UI 不动。

### 1. 本地内容覆盖层（存储层）

- `src/data/contentEdits.ts`：`ContentEdits = { districts, spots, deletedDistricts, deletedSpots, updatedAt }`，
  `STORAGE_KEY = 'ds.contentEdits.v1'`。
- `applyEdits(bundle)` 合并静态内容与本地覆盖：覆盖项整条替换；删除项剔除并同步清理
  `district.spots` 与 `city.districts` 的引用；返回全新对象，不修改入参。
- `staticRepository.loadContent()` 改为 `读原始 → applyEdits → 返回`；`mutateEdits` 写完即 `invalidateContent()`。
- `repository.ts` 扩展 `readContentEdits / saveDistrictContent / saveSpotContent / deleteDistrictContent /
  deleteSpotContent / resetContentEdits`，全部由 browser 实现，未来 `tauriRepository` 可整体替换。

涉及：`src/data/contentEdits.ts`、`src/data/repository.ts`、`src/data/staticRepository.ts`、`src/stores/data.ts`

### 2. 内容校验（运行态 + 构建期）

- `src/data/validate.ts`：`ALL_TAGS`、`validateSpot / validateDistrict / validateDraft / isEmptyContent`。
  坐标边界 经度 73–135.5、纬度 3–54；日期 `^\d{4}-\d{2}-\d{2}$`；空名/一句话/简介、悬空引用、重复 id 报错；
  >4 标签、美食缺分类、超长行程为建议。
- `scripts/validate-content.mjs`：`npm run validate` 在构建链路（`build-content → validate → tsc → vite build`）
  中跑通，校验结构 / 标签 / 日期 / 坐标 / 引用方向（内容→城市归属，不要求城市全量区县都有内容）；error 退出码 1。

涉及：`src/data/validate.ts`、`scripts/validate-content.mjs`、`package.json`

### 3. 数据面板（编辑器 UI）

- `src/components/data/DataPanel.tsx`：模态编辑。左栏按城市分组列出区县（已编辑打点 + 景点数）；
  主区含 基础信息 / 内容块 / 美食 / 景点 四段，实时 `validateDraft` 内联报错，dirty=false 或 error>0 时禁用保存。
- 保存走 `applyDistrictEdits`（写 spots+district、更新 map、标已编辑）→ `refreshPins()` + `updateMarkers()` 让 3D 与抽屉即时反映。
- 打开优先定位当前正在看的区县（`useNavigation.activeDistrictId`）。
- `src/components/data/fields.tsx`：`Field / TagPicker / PeopleEditor / FoodsEditor` 复用表单件。
- 顶部 `TopBar` 新增 `✎ 数据` 入口，显示已编辑区县数角标；`Shell` 的 Esc 优先关面板。

涉及：`src/components/data/DataPanel.tsx`、`src/components/data/fields.tsx`、`src/components/hud/TopBar.tsx`、`src/app/Shell.tsx`、`src/styles/app.css`

### 4. 导入 / 导出 / 重置

- `exportContentBundle(districtId?)` 下载单个区县或全量 bundle（`format: 'district-sandbox-content@1'`），可回写 `public/content`。
- `importContentBundleFile(file)` 校验后并入当前数据集：支持「仅景点」bundle 挂回已有区县；按已知 id 去重，非法项跳过并提示。
- `removeDistrictContent`（两步确认）整条剔除区县及其景点；`resetContent`（两步确认）清空覆盖层恢复静态内容。

涉及：`src/app/sandbox.ts`、`src/stores/data.ts`、`src/stores/ui.ts`

## v0.8（2026-10-20）· 体验修正 + 本地照片库

一次性回应用户 6 条反馈：场景抬升截面、区县自有美食、去过标记、城区文案、本地照片库、抽屉标题间距。

### 1. 选中抬升的截面重做（场景）
- 问题：城市 / 区县板块被选中或悬停时整体抬升，侧壁直接暴露、板底悬空，像一块漂浮的平板。
- 处理（`src/scene/plates.ts`、`src/scene/SceneManager.ts`）：
  - 板块轮廓线由「整条挤出棱线」改为「只描顶部轮廓」（`LineLoop`），侧面是一整块干净的面，
    不再露出一排细竖线；碎岛型区县（如淳安）本身是多边形，属数据形态，非缺陷。
  - 每个板块新增**抬升基座**：同形内缩 0.84 的柱体，从地面连到板底，顶部略高过板底 0.02 避免共面 z-fighting；
    基座带语义色微光与轮廓线，在暗场里读作「展台」而不是浮空平板。
  - 抬升由瞬时赋值改为**帧率无关的平滑过渡**（约 0.3s 到位 94%），基座高度跟随板高。
- 注意：淳安这类多岛区县的侧面仍是多根小柱，是地理数据形态；城市级板块为单轮廓，侧面已干净。

### 2. 区县详情改为「本区县美食 + 特产 · 非遗」
- 问题：抽屉里的「城市美食榜」取的是 `currentCity.foods`，选淳安县显示的是杭州美食。
- 处理：抽屉改为展示 **本区县 `foods`**（标题「在地美食」），点击仍走 `openLeaf` 美食卡；
  新增「特产 · 非遗」板块。城市级美食榜只留在城市面板（`CityPanel`），不再侵入区县抽屉。
- 数据模型：`District.specialties?: { name, kind: '特产'|'非遗', note }[]`；
  内容源 `scripts/content/*.mjs` 每个区县对象下新增 `specialties: [[名称, 类型, 说明], …]`，
  由 `build-content.mjs` 映射入 `districts.json`。本轮为 **35/38 区县录入 62 条**（徐汇 / 杨浦 / 长宁暂无把握条目，
  留空由用户在编辑器补；全部内容沿用「公开资料整理 · 待人工复核」口径）。
- 编辑器：`DataPanel` 新增「特产 · 非遗」段（类型二选一 + 名称 + 说明），`validate.ts` 同步校验

### 阶段 C 补丁：横穿中线的真正根因（基座被压扁）

上一版把「地图中部一根横线」归因于 `GridHelper` 的中心线色（已顺手统一为单色），但用户复看后指出**线还在**。这次用射线拾取 + 投影包围盒扫描定位到真凶：

- **现象**：安徽左侧、上海右侧各露出一段数十字像素的细横线（金色 / 青色 / 带暗蓝面），恰在地图中央纬线 z≈0 上。
- **根因**：`createPedestal` 里用 `mesh.scale.y = 0.001` 把基座「压平隐藏」。但基座是先 `rotation.x = -PI/2` 旋转的挤出体，**高度方向是局部 Z 轴（挤出方向），局部 Y 旋转后变成世界 Z（南北）**。`scale.y = 0.001` 压的不是高度而是「南北向足迹」——每个城市的基座被压成一片 1 单位高、横跨整城东西宽度的**薄墙**，贴在 z≈0 的中央纬线上；薄墙与板块在 z≈0 处足迹不重合的部分就露出板外，形成那两段细线（`stepPlateLift` 里同轴的 `pedestal.scale.y` 动画也是同一处错）。
- **修复**：`createPedestal` 改 `scale.z = 0.001`；`stepPlateLift` 里基座高度动画改用 `scale.z`。修复后基座足迹不再变形（`scale.y === 1`），静止时高度 0.02 藏于板内；选中抬升时 `scale.z` 长到 1 倍抬升量，仍是原来的「展台」效果（实测：选中浦东 targetY=0.55、板 y=0.54、基座 scale.z=0.56）。
- **验证**：`scripts/regression-phaseC.mjs` 新增 #7b「基座未压扁（无横穿细线）」——210 个城市基座 `scale.y≠1` 的数量为 0、最大高度 0.02、全场景「投影宽>40px 且高<9px」的细长板块为 0；并新增诊断脚本 `scripts/diag-sliver.mjs`（射线+投影扫描定位细线对象）与 `scripts/diag-pedestal.mjs`（基座缩放/归属）。回归 12/12 PASS。
- **经验**：给旋转过的挤出体改尺寸，先确认「挤出方向落到哪个世界轴」——`rotation.x=-90°` 时高度只能走 `scale.z`；`scale.y` 动的是平面足迹，且因为几何点用的是世界坐标，压足迹会把它整体拉向 z=0，看起来就是一条横穿全图的细线。

### 2. 点城市「放大的太大」

### 3. 收藏的小红心不好看 / 颜色不行 / 上下颠倒
- 旧轮廓是手搓贝塞尔（three.js 示例心形），其两个圆瓣在**下方**、尖端在**上方** → 渲染出来是倒置的爱心（用户说的「上下颠倒」）。直接翻转会带来法线/缩放问题，改为用经典心形参数方程生成：
  `x = 16sin³t / 16`，`y = (13cos t − 5cos2t − 2cos3t − cos4t) / 16`，84 段折线成 `Shape`，再 `computeBoundingBox()` 居中 → 天然「上方两瓣 + 下方一尖」。
