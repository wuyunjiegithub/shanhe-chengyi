# 山河城邑 · 设计文档

版本：v0.3
UI 视觉基线：`code.html`（可运行 Three.js 原型）+ `DESIGN.md`（设计系统）+ `screen.png`（效果图），均为仓库根目录文件。

## 1. 信息架构

### 1.1 布局模型：全屏 Canvas + 浮层 HUD

3D 画布全屏铺满（100vw × 100vh），所有 UI 元素以**浮层**叠加在其上，不占据固定列宽。这是与「管理后台三栏布局」的根本区别——地图是唯一主角。

```
┌────────────────────────────────────────────────┐
│ 顶部：品牌胶囊 · 居中搜索台(520px) · 遥测胶囊     │   ← 悬浮，无通栏背景
│                                                │
│  左侧   ┌────────── 3D Canvas ──────────┐      │
│  浮层    │   (城市/区县挤出板块 + pin + 雷达环) │      │
│  索引   │                                 │  右侧  │
│  (无底)  └──────────────────────────────┘  区县  │
│                                                │  抽屉(滑入)
│ 底部：重置视角 · 8标签胶囊 · 收藏/Esc/罗盘         │   ← 悬浮胶囊
└────────────────────────────────────────────────┘
```

### 1.2 层级与载体

| 层级 | 展示载体 | 交互 |
| --- | --- | --- |
| L1 区域总览 | 全屏 Canvas（城市板块，四省语义色） | 点击/悬浮城市 → 下钻 L2 |
| L2 城市地图 | 全屏 Canvas（区县板块，选中高亮） | 点击区县 → 右侧抽屉（L3） |
| L3 区县详情 | 右侧滑入浮层抽屉（毛玻璃） | 含天气卡 + 内容块 + 景点/美食 |
| Leaf 景点/美食 | 浮层卡片 / 抽屉列表 | 轻量浮层，点遮罩关闭 |

**导航状态机（Zustand）**

```
总览区 → (点击城市) → 城市地图 → (点击区县) → 抽屉打开（不离开 L2）
   ↑ Esc/返回            ↑ Esc/返回
附加：搜索命中 → 任意层级直达；pin 点击 → 在 L2 上弹卡片
```

## 2. 设计原则

1. **地图是唯一主角**：UI 全部浮层化（半透明白/毛玻璃），信息环绕而非遮挡。
2. **四省语义色**：沪青 / 苏蓝 / 浙绿 / 皖金，一眼分辨省域归属。
3. **暗色沉浸**：深空黑底 + 微光矢量线 + 雾效 + 粒子，板块/边界/pin 是唯一焦点。
4. **未录入降级**：灰色低饱和板块存在，不阻塞浏览。
5. **内容与空间解耦**：repository 层隔离数据，3D 只消费投影后几何。

## 4. 核心界面规范

### 4.1 顶部（悬浮）

- 左上：品牌胶囊「山河城邑 / 江浙沪皖」+ 坐标/倾角遥测
- 居中：520px 搜索台（胶囊，聚焦泛青光），展开玻璃下拉：最近搜索 + 分类结果（城市/区县/景点）
- 右上：遥测胶囊「41 市 / 区县已同步 · 地图渲染就绪」+ 天气在线/离线微标

### 4.2 左侧（悬浮索引）

- 无背景容器的纵向文字流，按省分组，与 3D 同步高亮
- 当前项：青底 + 左侧竖条 + `当前` 徽标；未录入项灰色

### 4.3 底部（悬浮胶囊）

- 左下：重置视角（`重置俯视 52°`）
- 居中：8 标签胶囊筛选条（单选，仅影响景点 pin/列表）
- 右下：收藏计数「认知触点」+ Esc 返回 + 罗盘

### 4.4 地图锚点卡（悬浮 HUD Pin）

- 激活城市上悬浮玻璃卡：名称 + 区县数 + 触点数 + 「点击下钻」提示
- 细引线连到 3D 坐标点的脉冲光点（呼吸动画）

### 4.5 区县详情抽屉（L3，右侧滑入）

从上到下：区县名 + 所属城市 + 收藏 → **未来 7 天天气卡** → 一句话推荐 → 标签组 → 内容块（历史/人文/名人/特色/美食）→ 主要景点列表 → 美食列表 → 底部操作（收藏区县 / 导出备份）。

### 4.6 卡片（景点/美食浮层）

- 景点：图片（16:9）+ 名称 + 标签 + 60–80 字简介 + 适合人群/时长/区县
- 美食：名称 + 品类 + 推荐店 + 一行推荐语 + 区县
- 轻量浮层，点遮罩关闭，不跳页

## 5. 天气模块设计（联网增强）

### 5.1 定位

区县天气是**唯一联网能力**。核心浏览/搜索/收藏/导出保持 100% 离线；天气断网时读缓存并标注「更新于」，无缓存时显示占位，不阻断其它内容。

### 5.2 数据源

**Open-Meteo Forecast API**（免 key、免注册、免费、CC-BY 4.0）。

- 入参：区县中心点 `lat/lng` + `timezone=Asia/Shanghai` + `daily` 字段
- 取字段：`weathercode`、`temperature_2m_max/min`、`precipitation_probability_max`、`windspeed_10m_max`
- WMO `weathercode` → 本地映射表（中文描述 + 天气图标）

### 5.3 请求链路

```
Rust command fetch_weather(lat,lng)  ← reqwest →  Open-Meteo
        │ 超时/重试/缓存读写
        ▼
WeatherRepository（Tauri command 返回结构化 JSON）
        ▼
Zustand weather store → 抽屉天气卡 / 城市概览条
```

走 Rust 侧请求以规避 CORS、统一超时重试、并落本地缓存。

### 5.4 缓存与离线

- 缓存位置：`src-tauri/data/cache/weather/{districtId}.json`
- 字段见需求文档 5.6；TTL 建议 3–6 小时，在线超期静默刷新
- 断网：读缓存 + 「离线 · 更新于 xx」；无缓存：显示「联网后获取 7 天天气」占位

### 5.5 UI 呈现

- **区县抽屉顶部**：毛玻璃「未来 7 天」卡，横向 7 个 mini cell（今天高亮），每 cell：星期 + 图标 + 最高/最低温 + 降水概率
- **城市悬浮卡（可选）**：一行 3 天概览
- **顶部遥测**：天气数据在线/离线微标 + 「更新于」

## 6. 技术设计要点

### 6.1 渲染分层

```
CanvasLayer（three.js：GeoJSON 挤出板块 + pin + 雷达环/粒子/雾）
OverlayLayer（HTML 绝对定位：搜索台、索引、抽屉、锚点卡、tooltip）
```

### 6.2 数据流

```
repository（本地 JSON/GeoJSON + 天气缓存）
  → 投影模块（经纬度 → 局部平面 + 归一化）
  → store（Zustand：层级、选中、筛选、收藏、天气）
  → scene（订阅 store 计算几何与材质）
```

### 6.3 落地要点

- 真实 GeoJSON 边界 + `ExtrudeGeometry`（原型 code.html 的八边形仅为视觉占位）
- 本地 npm 包替换 CDN（three.js / Tailwind / 字体全部本地化，满足离线 + 冷启动 ≤3s）
- Raycaster 拾取，pin 扩大点击热区；坐标/倾角 HUD 读真实相机状态

### 6.4 命名评估（结论）

知识原子单元是**区县**（历史/人文/美食/景点都挂载其下），省市仅为导航路径，故 `district-sandbox` 最准、可扩展。最终仓库名保留 `district-sandbox`。
