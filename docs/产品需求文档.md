# 山河城邑 · 产品需求文档

版本：v0.3
范围：江浙沪皖
形态：单机桌面客户端，唯一用户；核心功能无联网依赖，天气为唯一可选联网增强模块
技术方向：Tauri 2 + Vite + React + TypeScript + three.js

---

## 1. 产品定位

以「区 / 县」为最小浏览单元的地方游玩认知工具。用户按 **区域 → 城市 → 区县 → 景点 / 美食** 逐级浏览，
快速了解一个地方的历史、人文、名人、特色、美食和可游玩地点。

它不是导航工具、路线规划工具、订票平台、旅游攻略社区，也不是多用户产品。
它是**个人的地方游玩知识库** + **3D 空间索引**。

### 1.1 核心目标

1. 快速判断「这个地方值不值得去、有什么可看可吃」
2. 把零散信息沉淀为本地可编辑、可备份的结构化数据
3. 用 3D 地图建立空间记忆，而非靠列表和搜索框

### 1.2 明确不做

- 不做街道级导航与步行引导
- 不做路线推荐与行程编排
- 不做订票、预订、交易
- 不做账号、分享、UGC、评论
- 不把在线地图 API 作为地图或数据的依赖项
- 不做全国范围，MVP 只覆盖江浙沪皖

## 2. 用户与场景

唯一用户为产品使用者本人。

| 场景 | 描述 | 产品响应 |
| --- | --- | --- |
| 周末短途前查地方 | 想去某个城市，不知哪个区县值得去、天气如何 | 区域总览 → 城市 → 区县详情（含未来 7 天天气），10 秒内得到判断 |
| 临时决定去某地 | 只知地名，想快速判断值不值得 | 搜索直达区县或景点，相机飞入并打开卡片 |
| 旅行灵感浏览 | 无明确目的地，想扫一遍周边 | 3D 地图 + 标签筛选 + 收藏清单 |
| 个人知识沉淀 | 去过的、想去的、查到的内容想存下 | 本地 JSON 可编辑，收藏可导出备份 |

## 3. 范围与层级模型

覆盖江浙沪皖，约 40 个地级市、约 300 个区县。

```
区域总览（L1）── 以地级市为板块单位，省界仅做视觉分组
   └─ 城市地图（L2）── 展示该城市下 8–15 个区县板块
        └─ 区县详情（L3）── 右侧浮动抽屉，内容卡片 + 景点/美食
             └─ 景点/美食卡片（Leaf）── 轻量浮层，不跳页
```

层级要点：

- **省**：只做视觉分组，不做独立下钻层。
- **市**：区域总览层的最小板块单位。
- **区县**：产品知识的「原子单元」，所有内容（历史/人文/美食/景点）都挂在区县下。
- 内容按批次录入，**未录入的区县显示为低饱和「未录入」板块**，点击提示暂无内容，不阻塞浏览。

## 4. 功能需求

### 4.1 P0（必须做）

**3D 地图**

- 暗色桌面地图风格，区县/城市为挤出板块，细边界线，弱内发光
- 45–55° 倾斜俯瞰，限制相机极角与旋转范围
- 悬浮高亮，点击飞入下一级；Esc 或按钮返回上一级
- 选中板块抬高/高亮，其他板块变暗或轻微下沉

**区域与城市浏览**

- 江浙沪皖区域总览，地级市板块，省界视觉分组
- 点击城市进入区县地图
- 左侧纵向文字索引，与 3D 同步高亮

**区县详情抽屉**

- 区县名、所属城市、收藏按钮
- 一句话推荐语（最多两行）
- 3–5 个标签
- 内容块：历史、人文、名人、特色、美食
- 主要景点列表：5–8 条（缩略图、名称、一行简介、2 个标签）
- 美食列表：3–8 条（名称、品类/推荐店、一行简介）
- 底部操作：收藏该区县、导出本地备份

**景点与美食标记**

- 景点以 pin 显示在选中区县板块上，悬浮显示名称，点击弹出卡片
- 美食 P0 先在抽屉内以列表呈现，不单独做 pin 类型
- 景点卡片：图片、名称、标签、60–80 字简介、适合人群、建议游玩时长、所属区县
- 美食卡片：名称、品类、推荐店/区域、一行推荐语、所属区县

**搜索**

- 支持城市、区县、景点、美食名称搜索
- 结果带类型标签，最多 8 条
- 选中后相机飞到目标：城市 → 展开区县地图；区县 → 打开抽屉；景点/美食 → 飞到所属区县并高亮对应项
- 最近搜索最多 3 条，本地存储

**标签筛选**

- 固定 8 个标签：古镇、山水、博物馆、寺庙、亲子、拍照、徒步、历史文化
- 只过滤景点 pin 和列表，不做复杂组合筛选
- 美食复用「特色」或后续增加美食标签，MVP 不单做美食标签体系

**收藏**

- 收藏区县和景点，本地存储
- 收藏列表可查看、可导出 JSON

**数据与备份**

- 所有数据为本地文件，可手动编辑
- 「导出收藏 / 导出数据」入口
- 图片放本地目录，不依赖外链

### 4.2 P1（后置）

- 简单数据管理页：表单录入区县/景点/美食，避免手改 JSON
- 美食作为第二类 pin，用不同颜色或图标区分
- 景点/美食关联推荐
- 城市页热门区县列表，作为 3D 兜底入口
- 数据导入 JSON
- 区县未来 7 天天气预告（唯一联网增强模块：Open-Meteo 免 key，本地缓存兜底，断网降级展示）

### 4.3 P2（再考虑）

- 多区域扩展
- 真 3D 地形或建筑
- 行程编排
- 图片本地缓存管理
- 全局多标签组合筛选

## 5. 数据模型

### 5.1 区县数据

```json
{
  "id": "330110",
  "name": "余杭区",
  "city": "杭州市",
  "province": "浙江省",
  "oneLiner": "良渚文明与径山茶禅交汇的城郊山水区",
  "tags": ["历史文化", "山水", "亲子"],
  "history": "……",
  "culture": "……",
  "people": [{ "name": "沈括", "note": "……" }],
  "features": ["……"],
  "foods": [
    { "name": "径山茶宴", "category": "茶宴", "recommend": "径山寺周边", "note": "……" }
  ],
  "spots": ["spot-id-1", "spot-id-2"],
  "cover": "assets/330110/cover.jpg",
  "source": "……",
  "updatedAt": "2026-10-19"
}
```

### 5.2 景点数据

```json
{
  "id": "spot-id-1",
  "name": "良渚古城遗址公园",
  "districtId": "330110",
  "lng": 119.98,
  "lat": 30.39,
  "summary": "……",
  "image": "assets/330110/liangzhu.jpg",
  "tags": ["历史文化", "亲子", "拍照"],
  "hot": true,
  "suitableFor": ["亲子", "拍照"],
  "duration": "半天",
  "source": "……",
  "updatedAt": "2026-10-19"
}
```

### 5.3 城市与区域数据

```json
{
  "id": "330100",
  "name": "杭州市",
  "province": "浙江省",
  "districts": ["330110", "330102"],
  "intro": "……",
  "featuredDistricts": ["330110"]
}
```

### 5.4 美食数据

P0 阶段美食内嵌在区县数据中，不单独建文件；P1 若做美食 pin，再拆为独立 `foods.json`（字段类似景点，增加 `category`、`recommend`）。

### 5.5 数据来源与版权

- 区县边界：阿里云 DataV.GeoAtlas 或开源行政区划数据集，下载为本地 GeoJSON
- 不接入高德地图 API 作为地图或数据依赖
- 图片使用本地文件，标注来源与版权
- 内容标注来源与更新时间，AI 辅助起草需人工审核

### 5.6 天气缓存数据

按区县缓存最近一次 7 天预报，断网时兜底展示；`code` 为 WMO 天气码，本地映射为中文描述与图标。

```json
{
  "districtId": "330110",
  "fetchedAt": "2026-10-19T08:00:00+08:00",
  "source": "open-meteo",
  "tz": "Asia/Shanghai",
  "daily": [
    { "date": "2026-10-19", "code": 61, "tMax": 23, "tMin": 15, "precip": 40, "windKmh": 18 }
  ]
}
```

## 6. 技术架构

### 6.1 技术栈

| 层 | 选型 |
| --- | --- |
| 桌面壳 | Tauri 2 |
| 构建 | Vite |
| 前端 | React + TypeScript |
| 3D | three.js（可选用 @react-three/fiber） |
| 状态 | Zustand |
| 搜索 | Fuse.js |
| 地图数据 | GeoJSON + 局部投影 + ExtrudeGeometry |
| 存储 | 本地文件 + localStorage（收藏） |
| 天气 | Open-Meteo Forecast API（免 key、免注册）+ Rust reqwest 转发 + 本地缓存 |
| 打包 | Tauri bundle |

### 6.2 关键实现约束

- GeoJSON 经纬度投影到局部平面坐标，区县边界挤出为低高度板块
- 文字标签与卡片用 HTML overlay（CSS2DRenderer 或绝对定位），不用 3D 文字
- 相机下钻 0.5–0.8 秒 lerp 动画
- Raycaster 处理板块与 pin 点击，pin 扩大点击热区
- 数据访问抽象为 repository 层，UI 不直接调 Tauri API，便于以后替换存储实现
- 天气由 Rust 侧 `reqwest` 请求 Open-Meteo 转发给前端，规避 CORS、统一超时/重试，断网时回退缓存

### 6.3 仓库结构

```text
district-sandbox/
├── src/
│   ├── app/                 # 入口、路由状态、布局
│   ├── scene/               # three.js 场景、相机、拾取、动画
│   ├── components/          # 抽屉、卡片、搜索、标签、收藏
│   ├── data/                # repository、类型定义、投影工具
│   ├── stores/              # Zustand 状态
│   └── styles/
├── src-tauri/
│   ├── src/                 # Tauri commands
│   └── data/
│       ├── geo/             # 区县/城市 GeoJSON
│       ├── content/         # 区县、城市、景点、美食 JSON
│       ├── favorites.json
│       └── cache/weather/   # 天气缓存（按区县）
├── public/assets/           # 本地图片
├── scripts/                 # GeoJSON 转换、内容校验
└── docs/                    # 本文档、数据模板
```

## 7. 非功能需求

- **离线可用**：断网状态下完成全部浏览、搜索、收藏、导出；天气为唯一联网项，断网时读缓存并标注「更新于」
- **冷启动**：冷启动到可交互 ≤ 3 秒（本地数据量级）
- **性能**：区域 40 板块 + 单城 15 区县 + 每区县 8 pin，目标 60fps，最低 30fps
- **数据可读**：所有内容为 JSON/Markdown，可手动编辑、可版本控制
- **可备份**：收藏与数据支持导出 JSON，数据目录可直接复制备份
- **可维护**：新增一个区县只需增加 GeoJSON 和内容 JSON，不改代码

## 8. 里程碑与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M0 | Tauri+Vite+React 脚手架，GeoJSON 加载与投影 | 本地能渲染一个城市的区县板块 |
| M1 | 区域总览 + 城市下钻 + 相机动画 | 江浙沪皖 40 个城市板块可浏览、可点击 |
| M2 | 区县详情抽屉 + 内容块（含美食）+ 景点列表 | 一个区县 10 秒内可判断值不值得去 |
| M3 | 景点 pin + 景点/美食卡片 + 搜索空间定位 | 搜索景点能飞到所属区县并高亮 |
| M4 | 标签筛选 + 收藏 + 导出备份 | 断网可用，收藏可导出 |
| M5 | 内容填充 2–3 个城市，每城 8–12 个区县 | 连续使用一周仍愿反复打开 |

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 3D 可读性差、pin 点不准 | 限制相机角度、左侧列表同步、搜索兜底、扩大 pin 热区 |
| 内容录入痛苦导致烂尾 | 先做 2–3 个城市；模板化 JSON；P1 做表单；支持导入导出 |
| 3D 开发过度 | MVP 只做挤出板块 + pin + 相机动画，不做地形和建筑 |
| 数据丢失 | 数据目录独立备份；收藏导出 JSON；内容文件纳入版本控制 |
| 范围过大 | 区县分批录入；未录入板块低饱和显示，不阻塞浏览 |

---

## 10. 验收标准

1. 断网可完成：区域总览 → 城市 → 区县 → 景点/美食 → 收藏
2. 从点击区县到看到「一句话推荐 + 标签 + Top 景点」≤ 2 秒
3. 搜索任意已录入景点/美食，能飞到所属区县并高亮
4. 新增区县只需添加 GeoJSON 和 JSON，无需改代码
5. 数据目录可直接复制备份，收藏可导出 JSON
6. 连续使用一周后，仍愿意用它而非直接搜攻略
