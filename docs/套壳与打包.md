# 套壳与打包（Tauri 2）

前端是纯静态的 Vite + React 应用，套壳用 **Tauri 2**：Windows 出单个 exe，Android 复用同一份代码出 APK。
选它的原因只有一个 —— 一套 `src-tauri` 同时覆盖桌面与移动端，Android 不用再引 Capacitor。

## 一、工程结构

```
src-tauri/
├─ Cargo.toml              # package name 必须 ASCII（shanhe-chengyi），中文名只在 tauri.conf.json
├─ tauri.conf.json         # productName=山河城邑 / identifier=com.ankon.shanhechengyi
├─ build.rs                # tauri_build::build()
├─ src/main.rs             # 桌面入口，发布版隐藏控制台
├─ src/lib.rs              # 带 mobile_entry_point，Android 也走这里
├─ capabilities/default.json
└─ icons/                  # 由 scripts/app-icon.svg 用 `npx tauri icon` 生成，含 Android mipmap
```

关键配置：

| 项 | 值 | 为什么 |
| --- | --- | --- |
| `vite.config.ts` → `base` | `'./'` | 资源被嵌进 exe/apk 后走自定义协议，绝对根路径 `/assets/...` 会找不到文件 |
| `build.frontendDist` | `../dist` | Tauri 会把整个 dist 打进产物，不是外挂目录 |
| `bundle.targets` | `["nsis"]` | NSIS 出安装器；`target/release/*.exe` 本身始终生成 |
| `webviewInstallMode` | `embedBootstrapper` | 安装包自带 WebView2 引导器，离线也能装 |
| `nsis.installMode` | `currentUser` | 普通用户权限即可安装，不触发第二次 UAC |
| `app.security.csp` | `null` | 照片墙大量用 `blob:` URL，上 CSP 会挡住 |

## 二、Windows：单个 exe + 安装器

### 前置环境
1. **MSVC 生成工具 + Windows SDK**（Tauri 在 Windows 只支持 MSVC 链路）
   - 一键脚本：双击 `install-buildtools.bat`（自动请求管理员，装到 `C:\VSBuildTools`）
   - 装完确认：`C:\VSBuildTools\VC\Tools\MSVC\<ver>\bin\Hostx64\x64\link.exe` 存在，且 `C:\Program Files (x86)\Windows Kits\10\Lib` 有内容
2. **WebView2 运行时**：Win10/11 自带，本机版本 146.0.3856.97

### 构建
```bash
npm run tauri:build
```

### 产物
| 文件 | 说明 |
| --- | --- |
| `src-tauri/target/release/shanhe-chengyi.exe` | **便携单文件**，前端资源已嵌进 exe 资源段，双击即用、绿色免安装，可整份拷走（文件名取 Cargo 包名，故为 ASCII） |
| `src-tauri/target/release/bundle/nsis/山河城邑_<版本>_x64-setup.exe` | NSIS 安装器，开始菜单快捷方式 + 卸载入口 |

用户数据（收藏、游记、照片索引、IndexedDB 图片字节）落在
`%APPDATA%\com.ankon.shanhechengyi\`，删掉 exe 不影响，换台电脑也不会带走。

## 三、Android：APK

### 前置环境（本机实际配置）
- Rust 安卓目标：`rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android`（四个已装）
- Android SDK：`D:\devSoft\android-sdk-windows`（platform-tools / platforms;android-35 / build-tools;35.0.0 / ndk;27.2.12479018）
- JDK 21：`D:\java\jdk-21.0.3`
- 环境变量：`JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME`

### 构建
```bash
npm run tauri:android:init    # 首次生成 gen/android（Gradle 工程）
npm run tauri:android:build   # 四目标 universal APK
```
产物在 `src-tauri/gen/android/app/build/outputs/apk/universal/release/`。

**本机（16GB 内存）只出 arm64 单目标版**——四个目标并行编译会击穿页面文件
（`rustc-LLVM ERROR: out of memory` / `os error 1455`）。单目标构建：

```bash
npx tauri android build --target aarch64
```

### Windows 上的两个坑（已处理）
1. **jnilibs 符号链接失败**：tauri CLI 把编好的 `.so` symlink 进 `app/src/main/jniLibs/`，
   Windows 无开发者模式时建链失败、落成 **0 字节文件**，打出来的 APK 只有 1.7MB、装上必崩。
   修复：手动 `cp` 实体 `.so` 覆盖，再用 Gradle 单独打包并**排除 rust 构建任务**（否则
   CLI 的 android-studio-script 会把 symlink 重做一遍）：
   ```bash
   cd src-tauri/gen/android
   gradlew assembleUniversalRelease -PabiList=arm64-v8a -ParchList=arm64 -PtargetList=aarch64 -x rustBuildUniversalRelease
   ```
2. **Gradle 守护进程缓存启动环境**：改过 `JAVA_HOME` 等变量后必须 `--stop` 杀掉旧 daemon，
   否则新环境传不进去；Kotlin 增量编译跨盘符（C: 注册表缓存 vs D: 工程）会假失败，
   `gradle.properties` 里设 `kotlin.incremental=false` 规避。

### 签名
`src-tauri/gen/android/app/build.gradle.kts` 里 release 签名**仅在密钥文件存在时启用**
（`file("../../../shanhe-chengyi.jks").exists()`）——密钥 `src-tauri/shanhe-chengyi.jks` 不入库，
克隆仓库的人不带密钥也能构建（退化为未签名包）。重新生成密钥：
```bash
keytool -genkeypair -keystore src-tauri/shanhe-chengyi.jks -alias shanhe-chengyi \
  -keyalg RSA -keysize 2048 -validity 10950
```

### 产物（v0.9.12）
| 文件 | 说明 |
| --- | --- |
| `app-universal-release.apk`（约 7.8MB） | arm64-v8a 单架构，`com.ankon.shanhechengyi`，versionName 0.9.12 / versionCode 9012，minSdk 24，已签名（v2 scheme）；内嵌 `.so` 约 6.1MB |

交付副本：`out/山河城邑-0.9.12-android-arm64.apk`。

> 桌面安装包：`out/山河城邑-0.9.12-windows-x64-setup.exe` / `山河城邑-0.9.12-windows-x64.exe`（version 0.9.12）。

> **打完必查**：`unzip -l xxx.apk | grep arm64` 看 `.so` 是不是 MB 级别（干净 `dist` 约 6MB，内含全部前端）。
> 顺便 `apksigner.bat verify xxx.apk`（退出码 0 即签名通过）。
> 若只有几 KB，就是踩了上面的 symlink 坑（打出来 1.7MB 空壳，装上必崩）。
>
> **体积异常变大时**：`vite.config.ts` 的 `emptyOutDir:false` 不会清旧包，`dist/assets` 会跨多次构建
> 累积旧的 `index-*.js`，被一起嵌进 exe / `.so`（曾把 exe 撑到 25MB、APK 撑到 29MB）。
> 出包前先删一次 `dist/`（或 `rm -rf dist`）即可回到 5MB / 8MB 级别。

## 四、套壳带来的行为差异（已处理）

| 问题 | 处理 |
| --- | --- |
| WebView2 / Android WebView 里 `window.showDirectoryPicker` 报 `NotSupported` / `SecurityError` | v1.2 起套壳内走 `TauriDisk`（tauri-plugin-fs 原生目录选择 + 读写），浏览器里才退到 FSA；两者都不可用时再退 `<input webkitdirectory>` 一次性导入 |
| 移动端布局 | v0.9 已加三段断点 + `pointer: coarse`，面板改成贴底抽屉 |
| 跨域天气接口（open-meteo） | 未设 CSP，WebView 内正常请求 |

## 五、坑位记录

- **提升权限的安装进程会被环境回收**：由 AI 会话 `Start-Process -Verb RunAs` 启动的 VS 安装器，会在会话回合结束时被杀掉，装成一半成品（`VC` 目录有、`link.exe` 和 Windows SDK 没有）。`schtasks` 被安全策略拉黑。最终方案是交付 `install-buildtools.bat` 由用户双击运行。
- **setup.exe 的参数**：直接调 `C:\Program Files (x86)\Microsoft Visual Studio\Installer\setup.exe` 必须显式给 `--productId` + `--channelId`（bootstrapper 才会自动注入），且 `--wait` 不是它的参数（会报 exit 87）。
- **package name 不能用中文**：Cargo.toml 的 `name` 必须 ASCII，中文应用名只在 `tauri.conf.json` 的 `productName` 里写。
