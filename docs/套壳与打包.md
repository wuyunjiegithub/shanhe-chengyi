# 套壳与打包（Tauri 2）

前端是纯静态的 Vite + React 应用，套壳用 **Tauri 2**：Windows 出单个 exe，Android 复用同一份代码出 APK。
选它的原因只有一个 —— 一套 `src-tauri` 同时覆盖桌面与移动端，Android 不用再引 Capacitor。

## 一、工程结构

```
src-tauri/
├─ Cargo.toml              # package name 必须 ASCII（shanhe-chengyi），中文名只在 tauri.conf.json
├─ tauri.conf.json         # productName=山河城邑 / identifier=com.ankon.shanhechengyi
├─ build.rs                # tauri_build::build()
├─ src/main.rs             # 桌面入口，发布版隐藏控制台
├─ src/lib.rs              # 带 mobile_entry_point，Android 也走这里
├─ capabilities/default.json
└─ icons/                  # 由 scripts/app-icon.svg 用 `npx tauri icon` 生成，含 Android mipmap
```

关键配置：

| 项 | 值 | 为什么 |
| --- | --- | --- |
| `vite.config.ts` → `base` | `'./'` | 资源被嵌进 exe/apk 后走自定义协议，绝对根路径 `/assets/...` 会找不到文件 |
| `build.frontendDist` | `../dist` | Tauri 会把整个 dist 打进产物，不是外挂目录 |
| `bundle.targets` | `["nsis"]` | NSIS 出安装器；`target/release/*.exe` 本身始终生成 |
| `webviewInstallMode` | `embedBootstrapper` | 安装包自带 WebView2 引导器，离线也能装 |
| `nsis.installMode` | `currentUser` | 普通用户权限即可安装，不触发第二次 UAC |
| `app.security.csp` | `null` | 照片墙大量用 `blob:` URL，上 CSP 会挡住 |

## 二、Windows：单个 exe + 安装器

### 前置环境
1. **MSVC 生成工具 + Windows SDK**（Tauri 在 Windows 只支持 MSVC 链路）
   - 一键脚本：双击 `install-buildtools.bat`（自动请求管理员，装到 `C:\VSBuildTools`）
   - 装完确认：`C:\VSBuildTools\VC\Tools\MSVC\<ver>\bin\Hostx64\x64\link.exe` 存在，且 `C:\Program Files (x86)\Windows Kits\10\Lib` 有内容
2. **WebView2 运行时**：Win10/11 自带，本机版本 146.0.3856.97

### 构建
```bash
npm run tauri:build
```

### 产物
| 文件 | 说明 |
| --- | --- |
| `src-tauri/target/release/山河城邑.exe` | **便携单文件**，前端资源已嵌进 exe 资源段，双击即用、绿色免安装，可整份拷走 |
| `src-tauri/target/release/bundle/nsis/山河城邑_0.9.0_x64-setup.exe` | NSIS 安装器，开始菜单快捷方式 + 卸载入口 |

用户数据（收藏、游记、照片索引、IndexedDB 图片字节）落在
`%APPDATA%\com.ankon.shanhechengyi\`，删掉 exe 不影响，换台电脑也不会带走。

## 三、Android：APK（下一步）

### 前置环境
- Rust 安卓目标：`rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android`
- Android SDK：`platform-tools`、`platforms;android-34`、`build-tools;34.0.0`、`ndk;26.3.x`
  （本机 `D:\devSoft\android-sdk-windows` 目前是个空壳，需要用 SDK Manager 补装）
- 环境变量：`ANDROID_HOME`、`NDK_HOME`
- Java 21（本机已有）

### 构建
```bash
npm run tauri:android:init    # 首次生成 gen/android（Gradle 工程）
npm run tauri:android:build   # 产出 apk / aab
```
产物在 `src-tauri/gen/android/app/build/outputs/`。
`src/lib.rs` 里的 `#[cfg_attr(mobile, tauri::mobile_entry_point)]` 已经为移动端写好了。

## 四、套壳带来的行为差异（已处理）

| 问题 | 处理 |
| --- | --- |
| WebView2 / Android WebView 里 `window.showDirectoryPicker` 存在但调用时报 `NotSupported` / `SecurityError` | `src/stores/photoLib.ts` 的 `bind()` 捕获这类错误后自动改用 `<input webkitdirectory>` 弹系统文件夹对话框；代价是拿不到持久化句柄，实时重扫失效，但能一次性导入整棵目录 |
| 移动端布局 | v0.9 已加三段断点 + `pointer: coarse`，面板改成贴底抽屉 |
| 跨域天气接口（open-meteo） | 未设 CSP，WebView 内正常请求 |

## 五、坑位记录

- **提升权限的安装进程会被环境回收**：由 AI 会话 `Start-Process -Verb RunAs` 启动的 VS 安装器，会在会话回合结束时被杀掉，装成一半成品（`VC` 目录有、`link.exe` 和 Windows SDK 没有）。`schtasks` 被安全策略拉黑。最终方案是交付 `install-buildtools.bat` 由用户双击运行。
- **setup.exe 的参数**：直接调 `C:\Program Files (x86)\Microsoft Visual Studio\Installer\setup.exe` 必须显式给 `--productId` + `--channelId`（bootstrapper 才会自动注入），且 `--wait` 不是它的参数（会报 exit 87）。
- **package name 不能用中文**：Cargo.toml 的 `name` 必须 ASCII，中文应用名只在 `tauri.conf.json` 的 `productName` 里写。
